## 核心发现

### 1. V6 `isProtected` 的真实作用（***** 已纠正 *****）

**之前误解**：认为 `isProtected = false` 会导致 V6 无视 `phoneme` 字段，将拼音回退到 `[a]`。

**实际情况**：
- `isProtected` 是**编辑器 UI 层面的"音素保护"开关**，不影响直接 JSON 修改后的加载
- 当用户在编辑器内手动修改歌词时，`isProtected` 决定是否根据新歌词自动更新音素
- **直接修改 JSON 文件时，`phoneme` 字段会直接被加载**，与 `isProtected` 无关

**大量 `[a]` 的真正原因**：原始 VPR 中 `phoneme` 字段本身就是 `"a"`（日文歌词转拼音后没有正确映射音素），而非被覆盖。

**修改 JSON 后仍看到旧音素的原因**：V6 编辑器有文件缓存，删掉同名文件再打开时，编辑器可能加载缓存中的旧版本。

**正确做法**：
- 输出修改后的 VPR 时**使用不同文件名**（如 `song_fixed.vpr`），避免缓存问题
- `isProtected` 设为 `true` 是一个**好习惯**（防止编辑器内改歌词时丢失音素），但不是加载音素的必要条件

### 2. V6 音素格式中的 `'` 是腭化标记（***** 重要 *****）

**发现**：V6 使用 `'` 表示日语腭化辅音（如 `b'`、`d'`、`t'`、`m'`、`p'`、`g'`、`k'`、`4'` 等）。这是日语特有的音素表示法，用于表示辅音在 `i` 元音前的腭化变体。

**常见腭化音素**：
| 拼音 | 音素 | 说明 |
|------|------|------|
| bi | `b' i` | b + i 腭化 |
| pi | `p' i` | p + i 腭化 |
| mi | `m' i` | m + i 腭化 |
| di | `d' i` | d + i 腭化 |
| ti | `t' i` | t + i 腭化 |
| ni | `J i` | 特殊：使用硬腭鼻音 `J` |

**教训**：不能简单地将拼音拆分为声母+韵母再拼接 X-SAMPA。`di` 不是 `d i`，而是 `d' i`。

### 3. 方括号 `[ ]` 只是 UI 渲染（***** 常见误解 *****）

**发现**：V6 编辑器在音素面板上显示 `[a]`、`[d' i]`、`[tS M]` 等格式，但这只是**视觉装饰**。

**JSON 中的 `phoneme` 字段**：
- 正确：`"d' i"`、`"tS M"`、`"S j a N"`
- 错误：`"[d' i]"`、`"d,i"`（不要用逗号）

**教训**：JSON 中永远不加方括号，用空格分隔 X-SAMPA 音素即可。

### 4. ü 系列拼音的日语音素映射规则

**发现 1：日语没有 `ü` 元音**
中文的 `ü` 必须映射为日语 `M`（う）。

**发现 2：零声母 ü 系列有隐含声母 `j`**
| 拼音 | 常见错误 | 正确音素 |
|------|---------|---------|
| yu | `M` | `j M` |
| yue | `M e` | `j e` |
| yuan | `M a n` | `j a n` |
| yun | `M n` | `i n` |

**发现 3：j/q/x + ü 的组合**
| 拼音 | 实际发音 | 正确音素 |
|------|---------|---------|
| jue | j + üe | `dZ j e` |
| que | q + üe | `tS j e` |
| quan | q + üan | `tS j a n` |

**教训**：ü 系列需要逐个检查映射，不能简单套用 "声母 + 韵母" 规则。

### 5. 映射方向必须搞清楚

**混淆点**：Lua 脚本 `JPN to CHN`（日语→中文）和 `CHN to JPN`（中文→日语）是相反方向。

**正确方向**：
- 日语音库唱中文 = 中文歌词 + 日语音素
- 这是 `CHN to JPN` 方向
- 对应脚本：`ChnToJpn.lua`

**教训**：读取 Lua 脚本时，先确认脚本方向（看映射的 source 和 target），避免反向应用。

## 工程工作流最佳实践

### 阶段 1：歌词适配（字音匹配）

1. 解析原始工程，获取每段音符数
2. 将中文歌词分段，确保每段字数 = 音符数
3. **断词检查**：节奏断开处不能断在词语中间
4. **PIT 适配**：歌词声调应与 PIT 曲线起伏方向匹配

### 阶段 2：音素映射

1. 建立拼音 → 目标语言音素映射表
2. 批量应用到所有音符的 `phoneme` 字段
3. 检查未映射的拼音（通常是生僻字或自定义词）

### 阶段 3：输出与验证

1. 输出到**新文件名**（避免 V6 编辑器缓存）
2. 彻底关闭 V6 编辑器后重新打开新文件
3. （可选）批量设置 `isProtected = true`，防止后续在编辑器内改歌词时丢失音素

### 阶段 4：试听修正

1. 检查音素面板
2. 试听修正

## 常见症状速查

| 症状 | 可能原因 | 快速修复 |
|------|---------|---------|
| 大量 `[a]` 音素 | 原始 VPR 中 `phoneme` 本身就是 `"a"`（未映射） | 应用正确的拼音→音素映射 |
| `di` 是 `[d' i]`，其他仍 `[a]` | 部分音素碰巧正确，部分未映射 | 应用完整映射表 |
| `yu` 不发音 | 音素是 `M` 而非 `j M` | 修正 ü 系列映射 |
| `ni` 听感不对 | 音素是 `n i` 而非 `J i` | 修正为 `J i` |
| `wen` 听感不对 | 音素是 `M n` 而非 `w e n` | 修正零声母映射 |
| 修改 JSON 后编辑器仍显示旧音素 | **V6 编辑器缓存** | 使用不同文件名，彻底关闭编辑器后重开 |
| 跨语种后某些字完全无声 | 使用了非法音素（如 `y`） | 替换为日语音素 |
| AI 轨道和传统轨道都失败 | `isProtected` 未设置 | 先锁定再映射 |
| 跨语种后某些字完全无声 | 使用了非法音素（如 `y`） | 替换为日语音素 |
| 蝴蝶合并后只有第一个字发音 | 合并拼音的音素未连续拼接 | 检查多字合并音符的音素 |

## CLI 工具设计原则

为 vsynth skill 新增的 CLI 工具遵循以下设计原则：

1. **通用性**：不硬编码任何特定歌曲/工程的音符、歌词或映射
2. **JSON 输出**：所有工具支持 `--json` 参数，便于自动化处理
3. **预览模式**：支持 `--dry-run`，修改前可预览结果
4. **轨道筛选**：支持 `--track` 参数，可单独处理某轨道
5. **映射可扩展**：支持内置预设（`ja`、`en`）和自定义 JSON 映射文件
6. **模块化**：每个工具独立可运行（`python tool.py`），也可作为模块导入
