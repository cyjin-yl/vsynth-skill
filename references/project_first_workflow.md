# 从工程出发：填词、调音、字幕和 PV 的交付检查

这份参考来自连续制作、试听返修和文件核对中暴露的问题。它不是“自动填满所有音符”的配方，也不把文件能解析等同于作品已经能唱。涉及跨语种时，先读 [Japanese V4 → Mandarin](japanese_v4_mandarin.md)。

## 1. 先建立来源与版本清单

记录输入文件的实际路径、大小、SHA-256、格式、编码、曲名与用途。文件名不证明内容：名为 4K 的视频未必是所需完整 PV；字幕、音频和工程也未必来自同一剪辑。先读工程、探测媒体流和时长，再处理。

原词、现成翻译、逐音符表、工程、参考人声、伴奏、用户最终修订词稿是不同来源。冲突必须列出来，不能静默用网上歌词覆盖用户确认稿。音符级分析以实际工程为依据；原意以明确提供的原词为依据。字幕的整句时间不能证明逐字时长。

保留原输入，只产生新输出。不要将音源、字体、受限 UST、完整歌词或用户私人材料提交到公共仓库。检查每个原作者 readme；“不再分发”不应在经验分享时被忽略。回归测试使用自造片段。

## 2. 三种时间单位不能混淆

- VOCALOID tick 的 PPQ 必须读工程，不应无条件假设 480。
- Synthesizer V 的四分音符是 **705600000 blick**。在 480 PPQ 下，一个 tick 才是 **1470000 blick**；1470000 不是每拍的 blick 数。
- UST Mode2 的 PBS/PBW 时间坐标用毫秒。UST 的 `PBS` 不是 VOCALOID 的 Pitch Bend Sensitivity。

UST 既有全局 Tempo，也可能在音符或休止事件上写 Tempo。先解析有效覆盖关系，再积分；位于 tick 0 的事件可能覆盖全局值。不要读到离谱的全局速度就把整首判坏，也不能对未检查的变速曲直接套恒速公式。

VSQX 音符时间是 part 内坐标。先加 part 起点，再处理 preMeasure。字幕零点、工程零点、视频零点、混音零点分别记录。字幕每个时间点从原坐标独立计算，不逐项累加已经四舍五入的时长。

## 3. mora、假名、音符、字头不是同一个东西

“一个汉字对应一个实际咬字位置”不等于“每个假名都塞一个汉字”。逐格标注：

1. 独立起音；
2. 同字元音延续；
3. 鼻音韵尾；
4. 极短过渡；
5. release、休止或音源专用呼吸样本；
6. 原有非词汇性和声。

`i-chi` 仍有两个辅音/元音起音，不能因为汉语数字“一”只有一字就吞掉 `chi`。`rin` 的鼻音尾又不必另起一个汉字。鼻音延续中即使有音高改变，也应保留该音高，不是删除音符。

`- い` 之类 VCV 音源标签不等于独立的 `-` 延音；先解析 alias。原有 release 格不一定应再拖长前字，原有呼吸样本也不等于歌词“息”。源字段、处理决定和原因都要保留。

## 4. 不用拆音拯救过长的中文

用户要求保留原格时，冻结 `(voice, absolute onset, duration, MIDI key, rest)`。优先改写整句，不把一个长音任意切成两个半长字。也不要占用原休止。

先检查最短格。十几毫秒的过渡格不能仅因 XML 装得下就填独立汉字。把这种格并入前字延续可能是合理的，但必须记录为具体适配决定；不能据此把所有带辅音的短格一律吞掉。

没有通用的“超过某毫秒就必然清楚”。短格中的单元音、塞音、擦音、复韵母难度不同；先生成目标声库小样，再判断。阈值只能标风险，不能当声学保证。

## 5. 先让词组和语气落稳

逐句同时查看起音、休止、音高跳进、长音与语义。不要让“被”悬在长休止前，也不要把一个词拆到两次明显的乐句停顿两侧。重要长音应尽可能落到实义词，而非为了凑格而增加的虚词。

禁止以“字数不够”为由自动补啊、吧、呢等衬词；禁止截断原意或随意重复最后一字。句法需要的助词与无意义填拍应分开判断。

重复可以承担表达：反复规劝、疼痛拟声、身份陈述，不必每遍强行找同义词。相反，知晓→成为、请求→命令等有意义的变化必须保住。保留引语是谁说的，不能把被质疑的口号误写成叙述者最终立场。

## 6. 声音匹配不等于另押一套中文韵

检查每个显著落点的元音开合、圆唇、前后位置、鼻尾、辅音和延长方式。原尾音收向 `su` 时，换成 `zang` 不能仅凭意义或汉字数判合格。

不要只检查最后一字：句中被旋律放大的字同样重要。汉语声调也不能简化为固定平仄交替表；字典声调、变调、旋律和语义重心需要结合试听。任何近音导致的语义收窄、意象增加、句法重排，都应在取舍表中明示。

## 7. 保留已有调音，但不假装跨引擎无损

UST Mode2 要读取 PBS、PBW、PBY、PBM；颤音另读 VBR。各字段的坐标和插值类型不能混用。Mode1 与 Mode2 不能不辨模式就相加。

导出 VOCALOID PIT 前，需要考虑源绝对音高与目标引擎基础滑音的差。若已经将源颤音烘焙进 PIT，关闭重复的原生颤音，避免叠加。跨引擎基础滑音模拟是模型，不是目标声库的实测输出。

VOCALOID PIT 的范围是 -8192 到 +8191，须与 PBS 一起解码。必须检查边界、参数事件时间、异常跳变、变速段和有效音符覆盖，不能只看曲线“不是平的”。

UST oto.ini、PreUtterance、Overlap、Envelope 和 resampler flags 对特定音源/引擎有意义，不存在全部字段到 V4 参数的一一映射。未迁移的项目单独列出。

## 8. VEL、音色和参考音频分开对待

VOCALOID 的 VEL 主要影响辅音长度/起音速度，不是 MIDI 式音量控制。DYN、BRI、BRE 的职责不同。VEL 的方向和实际效果应在所用引擎及声库验证，不可照搬 UTAU 的同名数值。

参考人声的 F0、能量、谱倾斜、HNR 等可以帮助观察，但不能直接等同于 PIT、DYN、BRI 或 BRE。RMVPE 估计音高，不会输出 VOCALOID 的明亮度或气声旋钮。分离伪影、混响、和声、擦音和八度错误都可能污染测量。

保留原始测量、置信度、筛选规则和音频时间映射；不要悄悄把八度修正后的曲线称为未经处理的原唱曲线。人工/启发式音色控制标注为候选，并附中性音色对照。没有取得音频或没有运行模型，就不能报告“已提取”。

## 9. 对应声部不是按数组索引复制

和声可能漏拍、重复、延迟、分组或使用不同的时值。用原音节顺序、绝对时间和已知段落共同匹配，保留歧义日志。一首歌中同时唱不同词的回声，不应被“同时起音必须同词”的规则抹掉。

拆轨按明确的声部和声库需求进行。拆轨后重新验证各轨的基础滑音和参数零点，不直接复制相对于另一条音符序列的 PIT。

## 10. 字幕是可复核的派生物

从确定的字位和时间映射生成 LRC/SRT。延音不重复显示新汉字。原唱字幕与中文演唱字幕可以共用用户确认时间轴，但必须说明日文字幕也对应中文版音频，而不是原版视频独立打轴。

用户手改的词句、标点、全角空格、分句和清屏点优先；之后的更新不能悄悄退回旧稿。SRT 终点需要明确策略：下一时间点、实际尾音，或显式清屏。给出偏移正负方向，不依赖各播放器对 offset 标签的一致解释；可以直接平移所有时间戳。

## 11. PV 替字不是普通字幕覆盖

先测源片实际构图、句子出现与完全出屏的时间、字号层级、运动和文字遮住的内容。大花字、伪字、微小注音、短暂闪帧、引号和标点都进入逐镜头清单；可结合原工程和原词辨别难认字。

固定画布字位与共享镜头运动必须分离。某些 PV 中的字是原位出现并短暂变为随机字符，不是从上方飞入，也不是整列展开。随机字与正字必须互斥。镜头向下走时，旧字向上自然离屏；不要到任意时长就删除。场景确有硬切、擦除或换字时再单独建模。

对每个字位记录局部坐标、显现/落定/替换/出屏时间。共用刚性运动下，保守包围盒的静态不相交可排除同组碰撞；不同运动组、缩放旋转和字形变化仍需逐帧检查。静态遮罩跟不上快速运动时要重新追踪，不靠不断放大遮罩侵蚀人物。

中文与日文字数、字形不同；替代字体和补底不可能证明整幅图像“逐像素无损相同”。展示同步对照与真实误差/修补边界，不将模板匹配残差当整幅画面误差。

## 12. 交付验收分层

分别报告：文件解析；字段/几何对比；参数/音素静态检查；编辑器加载；目标声库渲染；试听；字幕同步；视频全片解码；混音对比。没有执行的层级必须写“未执行”。

视频检查不只探头尾：完整解码并检查各段，音频核对采样率、长度、时间戳、编码延迟/预卷和多个窗口。下载失败不要只换名字；检查损坏、大小和实际文件，必要时给小体积版。成品链接必须对应已生成且确实存在的文件。

修改日志说明改变了什么、保留了什么、证据是什么。脚本可复现与真实声库可唱是两件事。不得捏造子代理审阅、独立批准、已试听或已经成功运行的模型。
